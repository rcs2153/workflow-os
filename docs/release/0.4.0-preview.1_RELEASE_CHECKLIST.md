### RustSec Feed Policy

The required security job fetches official RustSec `main`, reports its
resolved commit and age, and audits those exact bytes without refetching.
Missing, malformed, future-dated, or more than seven-day-old feed metadata
fails the job. A malformed advisory or audit failure also fails the job.
A green check records a point-in-time scan; rerun with current RustSec for
the publication decision instead of reusing old CI.

The repository release maintainer owns any exceptional pin. If upstream
data temporarily cannot be parsed, record a reviewed issue with an owner,
reason, exact official revision, upstream remediation link, and an explicit
expiry within seven days. A pin must pass the same freshness limit and fail
at expiry; wire that expiry into the required job as part of the exception.
Remove the pin as soon as upstream is usable. Do not waive advisories or
freshness to obtain a green check. No exception is active.

### Native Candidate Dispatch And Recovery

After the helper passes focused review, a separate governed dispatch phase
must bind the exact current `main` SHA, both native targets, and one persistent
operator-owned claim directory (mode `0700`) on a local filesystem. All callers
must share that directory. Keep it outside the checkout and away from cleanup,
snapshot restore, or competing ownership. Manual dispatch and dispatch from a
second directory are outside the duplicate-prevention boundary.

Use `node scripts/dispatch-native-candidate.mjs --source-commit <sha> --target
<target>` for read-only discovery. Authorized dispatch adds
`--dispatch --state-dir <private-directory>` and explicitly supplies an
Actions-write `GH_TOKEN` through the operator's environment. The helper
does not itself grant or verify the governed phase approval. Use
`aarch64-apple-darwin` or `x86_64-unknown-linux-musl` as the target.

An existing bound run prevents a send, even if cancelled or failed. A local
claim left behind by failure or interruption also prevents any resend.
Reconcile using read-only discovery with the same `--state-dir` and without
`--dispatch`. A dispatch reply is persisted before reconciliation, and a
different inventory ID fails closed even after restart. An inventory-only
result without a stored reply is an observation, not a matched reply. Zero
results do not mean no dispatch occurred. Never remove or replace a claim
or reply to force a retry. An observed run is not candidate acceptance:
verify its attempt, exact inputs, terminal
result, and artifact evidence separately. Multiple runs or disagreement
require operator review. This shell-side guard is not a global GitHub
exactly-once guarantee, and it cannot make the final ref check atomic with
the POST. The workflow still rejects any source/workflow revision mismatch.
