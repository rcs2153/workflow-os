# Workflow OS 0.3.0-preview.1 — Governed Execution and Continuity Preview

Workflow OS `0.3.0-preview.1` moves the project from governance primitives to
composed, inspectable local execution.

The kernel now binds governed work to immutable run identity, current
authority, policy, checks, approvals, evidence, side effects, durable events,
reports, and lawful continuation.

## Highlights

- governed sequential multi-step local workflows;
- proof-bound approval presentation and fresh-fact resume checks;
- proportional governance with quiet capture, visible disclosure, blocking
  approval, and denial;
- durable WorkReports and explicit create-only local report artifacts;
- bounded existing-repository onboarding and workflow authoring;
- filesystem, SQLite, and PostgreSQL preview state paths;
- private trusted-host no-write execution compositions;
- single-tenant no-write hosted alpha and optional OpenShell contracts; and
- narrow GitHub PR-comment and managed draft-PR sandbox proofs.

The new first-run quiet-success path performs real bounded posture analysis,
runs authoritative project validation, and persists one local WorkReport.
Complete low-risk facts can proceed without an approval record; escalated work
still blocks on proof-backed approval.

## Important Boundaries

This remains a preview. It is **not**:

- production-ready or multi-tenant;
- a general agent runtime or autonomous scheduler;
- arbitrary shell or repository-command execution;
- broad GitHub, Jira, CI, cloud, SaaS, or HTTP write support;
- enterprise RBAC/IdP/policy administration;
- a stable CLI JSON or persisted-state compatibility promise; or
- Level 3/4 autonomy enablement.

Mock skills demonstrate kernel sequencing only. Hosted, OpenShell,
trusted-host, PostgreSQL, and provider-write surfaces are bounded alpha/proof
paths, not production support claims.
