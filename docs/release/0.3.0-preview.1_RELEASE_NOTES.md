# Workflow OS 0.3.0-preview.1 Release Notes

Release title: **Workflow OS 0.3.0-preview.1 — Governed Execution and Continuity Preview**

## Release Posture

Workflow OS `0.3.0-preview.1` is a public preview of composed local governance:
the kernel can bind execution to immutable run identity, current authority,
policy, checks, approvals, evidence, side effects, durable events, reporting,
and lawful continuation.

This release is for maintainers, infrastructure and security engineers, and
teams evaluating governed agent work. It is not a production control plane,
general agent runtime, broad write-adapter framework, or autonomous scheduler.

## What Is New

### Governed execution

- Deterministic sequential multi-step local workflows.
- Immutable workflow, skill, policy, handler, schema, and input commitments.
- Restart-safe events, rehydration, bounded retry/escalation, cancellation,
  denial, and terminal-state enforcement.
- Missing handlers fail closed instead of simulating execution.

### Approval, authority, and proportional governance

- Approval presentation proof binds the exact scope shown before sensitive
  approval decisions.
- Approval resume reassesses current facts and rejects stale, missing,
  ambiguous, or substituted context where the selected path requires proof.
- Scoped capability, current-authority, required-context, independent-check,
  handoff, and hook models support bounded governed compositions.
- Core can select quiet capture, visible disclosure, blocking approval, or
  denial from complete bounded inputs. Callers do not choose the route.

### Evidence, side effects, and reports

- EvidenceReference and SideEffect vocabulary with durable event and audit
  foundations.
- WorkReports disclose work, evidence, decisions, checks, approvals, side
  effects, incomplete work, limitations, risks, and operator handoff.
- Explicit create-only local report artifacts use referential-integrity and
  approval/side-effect gates on selected paths.

### Existing-repository onboarding

- `init-repo-governance` preserves unmanaged `AGENTS.md` guidance by default.
- `first-run` performs bounded repository posture analysis from allowlisted
  metadata without reading arbitrary source or running repository commands.
- Review-only recommendations can become inactive drafts, pass preflight and
  stewardship review, then be promoted explicitly.
- `first-run --write-report-artifact` runs the new exact low-sensitivity
  artifact contract, executes authoritative project validation, and persists
  one local WorkReport. Exact complete low-risk facts proceed without an
  approval record; escalation remains proof-backed.

### Continuity, state, and bounded execution hosts

- The kernel models execution windows, executor yields, typed waits, resume
  directives, attempt outcomes, and durable continuation.
- SQLite provides reviewed atomic continuity operations and explicit staged
  migration/activation.
- PostgreSQL provides shared-state conformance, fenced hosted claims,
  reconciliation, and backup/restore rehearsal.
- A private local trusted-host crate composes fixed no-write check profiles and
  bounded redispatch. It is not a public arbitrary-command runner.
- A single-tenant no-write hosted alpha and optional OpenShell no-write
  contracts remain experimental evaluation surfaces.

### Integrations

- The `0.2.0-preview.1` fixture-first, opt-in live read-only GitHub, Jira, and
  GitHub Actions adapters remain available.
- One GitHub PR-comment path and one managed draft-PR helper demonstrate
  explicit sandboxed provider writes after kernel gates. They are narrow proof
  paths, not general write support and not enabled automatically.

## Upgrade From 0.2.0-preview.1

All Rust crates and TypeScript packages move to `0.3.0-preview.1`.

This v0 minor preview includes intentional evolution of Rust APIs and
experimental CLI JSON. Rebuild downstream code and review current docs.

No automatic persisted-state migration is claimed. Keep old preview state for
evidence and prefer fresh state for evaluation. Existing canonical repository
scaffolds can be upgraded additively:

```sh
workflow-os init-repo-governance
workflow-os validate
workflow-os first-run
```

Customized conflicting scaffold files are not overwritten silently.

## Security And Trust Boundaries

- Unknown, incomplete, stale, or ambiguous safety-relevant facts fail closed.
- Provider credentials remain opt-in and must not appear in specs, fixtures,
  docs, screenshots, issues, or pull requests.
- Recorded artifacts prefer references and bounded summaries over raw payloads.
- Deterministic redaction is not enterprise DLP.
- `serde_yaml` remains accepted only for trusted local, Git-reviewed specs.
- Hosted alpha, OpenShell, trusted-host, and provider-write paths require their
  exact documented boundaries; their presence does not imply production
  isolation or broad runtime support.

## Not Included

- Production multi-tenant hosting, high availability, SLOs, or enterprise
  identity/RBAC/IdP administration.
- A general agent runtime, recursive agents, agent swarms, or production nested
  harness execution.
- Arbitrary repository command execution by default.
- Broad GitHub, Jira, CI, cloud, SaaS, or generic HTTP mutation support.
- A production scheduler that continuously redispatches executors.
- A complete operator UI, automatic reasoning-lineage capture, or stable CLI
  JSON contract.
- Level 3/4 autonomy enablement by default.
