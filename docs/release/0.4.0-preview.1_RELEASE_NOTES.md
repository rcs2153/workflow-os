# Workflow OS 0.4.0-preview.1 Release Notes

Release title: **Workflow OS 0.4.0-preview.1 — Governed Authority and Repository Adoption Preview**

Status: preparation record; not yet published

## Release Posture

Workflow OS `0.4.0-preview.1` prepares the current local governance kernel
under a new immutable identity. It preserves the published
`v0.3.0-preview.1` tag and release as historical evidence rather than moving
that identity to newer source.

This preview is for maintainers, infrastructure and security engineers, and
teams evaluating governed agent work. It is not a production control plane,
general agent runtime, broad write-adapter framework, or autonomous scheduler.

## Highlights

### Authority and approval integrity

- Approval presentation proof binds the exact scope shown before approval.
- Sensitive resume paths reassess current facts and reject stale, ambiguous,
  substituted, or incomplete context.
- Scoped capability and external-action authorization models preserve bounded
  authority without treating standing delegation as unlimited permission.
- Proportional governance can select quiet capture, visible disclosure,
  blocking approval, or denial from bounded current facts.

### Continuation and context

- Immutable run inputs and resolved execution context protect approved work
  from definition changes between approval and resume.
- Authoritative continuation projects lawful next actions from durable kernel
  state instead of conversation memory.
- Context inventory, source coverage, replacement-executor delivery, and
  post-compaction understanding foundations preserve orientation without
  granting authority.

### Repository adoption

- Existing `AGENTS.md` content is preserved by default.
- First-run inspects allowlisted repository metadata and produces concise or
  verbose posture without reading arbitrary source or executing repo commands.
- Recommendations can become inactive drafts and pass preflight, stewardship,
  promotion, catalog inspection, repair proposal, and archive stages.
- The primary first-run path can persist one real local WorkReport backed by
  authoritative project validation.

### Runtime and provider boundaries

- Durable local, SQLite, and PostgreSQL state paths cover bounded recovery and
  shared-state evaluation.
- Trusted-host and hosted-alpha compositions remain fixed, no-write or narrowly
  bounded surfaces rather than general command runners.
- GitHub read-only fixtures, PR-comment proof, and managed draft-PR proof remain
  explicit sandbox paths, not general provider mutation support.
- Active provider user agents derive from the crate version so release identity
  cannot silently drift between clients.

## Upgrade Notes

All four Rust crates, the root npm package, and
`@workflow-os/sdk-typescript` move together to `0.4.0-preview.1`.

This v0 minor preview intentionally evolves experimental Rust APIs, CLI JSON,
and local runtime contracts. Rebuild downstream code and review the current
product contract. No automatic persisted-state migration is claimed.

## Not Included

- production multi-tenant hosting, high availability, or SLOs;
- enterprise identity, RBAC, IdP, or steward administration;
- arbitrary shell or repository-command execution by default;
- broad GitHub, Jira, CI, cloud, SaaS, or generic HTTP mutation support;
- a continuously operating autonomous scheduler;
- recursive agents, agent swarms, or production nested harness execution;
- a stable CLI JSON or persisted-state compatibility promise; or
- Level 3/4 autonomy enabled by default.

## Publication Boundary

Version alignment does not publish this release. A later governed phase must:

1. admit a clean exact-commit final native candidate;
2. verify target, binary version, manifest, checksum, install, and uninstall;
3. freeze the candidate source and workflow revisions;
4. obtain focused and independent assurance where required; and
5. separately authorize the tag, GitHub Release, assets, packages, and any
   announcement.
