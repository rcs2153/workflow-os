## Blocking Corrections Before Source Freeze

1. **P1 package onboarding.** Make the packager ship binary-first instructions
   rather than the source-contributor README verbatim. From the extracted
   archive, document install, PATH (including the prefix override
   `WORKFLOW_OS_INSTALL_DIR`), version, first-run, and uninstall. Ship the
   targets of local links or link to the exact source revision. Cover the
   release scope, two examples, current product contract, harness quickstart,
   explainer, engineering standard, roadmap, contributing and security links
   that were broken in the old package. An extracted-package test must verify
   the flow and all links without a source checkout or Rust/Node toolchain;
   both native artifact trials must follow the same instructions. Keep the
   installer guards and state-preservation assertions.
2. **P1 executable approval demo handoff.** The documented
   `workflow-os --mock-all-local-skills run local/first-run-governance`
   emits an approval command without the required mock flag, failing with
   `executor.selected_project_validation.current_bundle_handlers_mismatch`
   at both aggregate and authored gates when copied. Render a command that
   restores the exact bound handler posture, or remove the caller-restated
   flag requirement without relaxing matching. Use fresh processes to run
   every emitted continuation command through completion and denial, changing
   only explicit actor/reason placeholders. Cover exact replay, changed
   inputs, mismatch rejection, and ordinary runs that must not silently
   activate mocks. No authority extension or execution evidence from mocks.

## Follow-Ups With Explicit Disposition

- **P2 default help.** Keep discovery focused on initialize, validate,
  first-run, run, approve, status, inspect, authoring and state health; point
  to installation guidance. Move launch/recovery preflights, delegated provider
  continuation, fixture authority management and synthetic recovery to explicit
  operator help. Test default and explicit help and unchanged command routing.
- **P2 terminal next-action.** Replace the exit-3 continuation error for
  valid terminal runs with exit zero, observed terminal outcome and no-action
  guidance pointing to status/inspect. Keep invalid identity, corrupt state
  and unsafe ambiguity as errors. Test human and JSON output, local and fixture
  routing, completed and failed/denied states, and zero mutation. Do not report
  a failed run as successful execution; exit zero describes the query.

Implement and validate these P2s before the freeze when feasible. If a P2
cannot land in the candidate, the admission record must explicitly name its
impact, follow-up owner and disposition. Neither disposition can waive a P1.
