## Findings

### P2: installer follows a dangling destination symlink

The generated installer checks the destination with `-e`. A dangling symlink
therefore appears absent, and `cp` follows it to create the binary outside the
selected installation directory without `--force`. The independent reviewer
reproduced that behavior. It conflicts with the documented install boundary.

Future hardening should reject destination symlinks, including dangling ones,
and use an atomic destination-creation boundary. The separate publication
decision must explicitly accept, defer, or block on this risk; this assurance
record does not decide it.

### P2: Linux candidate evidence is less complete than macOS evidence

The Linux `candidate-evidence.json` records its archive hash but omits
`binary_sha256` and `binary_shape`. Those facts remain present in the package
manifest, active release-state projection, hosted verification result, and the
independent reviewer's recomputation. The omission did not invalidate the
candidate, but a future candidate-evidence hardening should make both native
targets symmetric.

### P2: current product-contract blocker text was stale

The product contract still listed validator-assurance work, independent review,
and exact-source re-candidating as wholly outstanding. Those gates are now
closed for their documented boundaries. This evidence update corrects that
conservative drift without expanding the product claim.
