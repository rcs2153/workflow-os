# 0.4.0-preview.1 Hardened Candidate Publication Decision

Status: **candidate admitted; external publication transitions remain unauthorized**

## Decision

The hardened `0.4.0-preview.1` macOS arm64 and Linux x86-64 musl candidate pair
is admitted for a separately authorized publication execution.

The exact source is
`6f8a38b080a21189dcfd82297f0c5917483b61ba`. Exact-source CI run
`42172009453` passed all nine required jobs. Accepted macOS run `42173154695`
and Linux run `42173177138` completed successfully on attempt 1. Independent
assurance against merged evidence commit
`85ff87825f8acf7a97c50ba5175ace11dc1aeb8d` reproduced the artifact digests,
archive and binary checksums, manifests, native shapes, installer defenses,
evidence symmetry, release authority, and terminal-green CI. It found no P0 or
P1 finding and no artifact-integrity blocker.

This decision resolves the prior publication denial for candidate quality. It
does not set `publication_authorized` to true and does not authorize or perform
tag creation, GitHub Release creation, asset upload, registry publication, or
announcement. Those irreversible transitions require a separately scoped
execution authorization that enumerates each action and binds it to this exact
source and artifact pair.

## Finding Classification

### Accepted pair: prior release blockers are corrected

The generated installers reject regular and dangling destination symlinks with
and without `--force`, use bounded no-follow destination admission, and preserve
ordinary install, overwrite refusal, explicit replacement, uninstall, and
state-preservation behavior. Both candidate-evidence records carry the required
binary hash, native shape, machine, source, workflow, archive, and authority
facts. The defects that caused the previous publication denial are therefore
closed for this pair.

### P2 process finding: candidate dispatch was not operationally once-only

The first macOS request created accepted run `42173154695`. A local wrapper
failure caused duplicate run `42173175053`, which was cancelled after exact-SHA
inventory exposed it. GitHub recorded zero jobs and no artifact for the
cancelled run. The accepted macOS and Linux candidates each came from one
successful attempt-1 run and remain attributable to the exact source.

This incident does not invalidate the admitted artifacts. It does block any
future candidate dispatch until an idempotent exact-source helper or connector
records the intended transition, reconciles ambiguous responses before retry,
and fails closed when a bound run already exists.

   digests match the release-state record;

   independently preserved source with the same verified bytes has been
   explicitly admitted;
4. `v0.4.0-preview.1` does not already identify a conflicting object and no
   conflicting GitHub Release exists;
5. the separately approved transition set explicitly names tag creation,
   GitHub Release creation, each asset upload, package publication posture, and
   announcement posture;
6. the immutable head and evidence remain unchanged throughout execution; and
7. every completed, denied, skipped, or still-available transition is recorded

The accepted Actions artifacts expire on 2026-11-13. Admission does not suspend
that retention policy. If the authorized execution cannot re-establish the exact
verified bytes after expiry, the admission lapses and a new exact-source
candidate pair is required.
