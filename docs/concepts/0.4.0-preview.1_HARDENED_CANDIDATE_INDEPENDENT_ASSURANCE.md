## Findings

### P2: candidate dispatch was not operationally once-only

The first macOS request created accepted run `42173154695`. A local wrapper
error caused duplicate run `42173175053`, which was cancelled after exact-SHA
inventory exposed it. GitHub showed zero jobs and no artifact for the cancelled
run. Linux run `42173177138` was unique.

This does not taint the accepted pair: only one successful attempt-1 artifact
per target is admitted, the duplicate produced no candidate output, and the
incident is disclosed in the active transfer record. Before any future
candidate dispatch, Workflow OS should use an idempotent exact-source helper or
connector path that records the intended transition, reconciles ambiguous
responses before retry, and fails closed when an exact-source run already
exists.
