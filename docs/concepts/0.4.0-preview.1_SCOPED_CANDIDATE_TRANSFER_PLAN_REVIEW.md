# 0.4.0-preview.1 Scoped Candidate Transfer Plan Review

Status: accepted after blocker correction

## Scope

This owner-conducted maintainer and release-security review evaluates the
[`0.4.0-preview.1` Scoped Candidate Transfer
Plan](../implementation-plans/0.4.0-preview.1-scoped-candidate-transfer-plan.md).
It is not independent external security assurance and does not authorize a
workflow dispatch, artifact upload, tag, release, package publication, or
announcement.

## Blocker Found

The initial plan selected one unpublished GitHub draft release as candidate
staging. That design was bounded and kept publication unauthorized, but review
rejected it for two reasons:

1. a draft release creates the future publication object early and exposes a
   one-click accidental publication path to users with push access; and
2. current GitHub-hosted public runners provide native arm64 macOS, so the
   accepted macOS candidate can be rebuilt and retained as a seven-day Actions
   artifact under the same contract as Linux.

The original premise that an already-built local archive cannot be inserted
into Actions artifact storage through a supported out-of-run upload path was
correct. The conclusion that a draft release was therefore necessary was not.
The safer answer is to reset the candidate source after adding the missing
native workflow and rebuild both targets once from the exact same reviewed
commit.

## Corrected Boundary

The corrected plan:

- adds one manual, read-only, native arm64 macOS candidate workflow;
- reuses the accepted Linux candidate workflow;
- requires workflow definition and candidate source to be the same exact
  post-merge commit;
- requires native binary execution, not cross-compilation inference;
- stores each target in one immutable seven-day Actions artifact;
- binds dispatch, ambiguity reconciliation, run identity, artifact identity,
  checksums, and expiry;
- supersedes rather than rewrites the earlier candidate evidence;
- reruns frozen validation against the new exact source;
- keeps independent assurance open; and
- creates no draft release, tag, public asset, registry package, or
  announcement.

## Security Assessment

The corrected design removes the accidental-publish surface and uses a storage
primitive with explicit automatic expiry. It preserves exact-source symmetry
across targets and makes any later workflow or source change invalidate both
candidates. Ambiguous dispatch cannot be blindly retried, missing hosted
artifacts cannot be replaced with local output, and evidence commits remain
distinguishable from candidate source.

The plan truthfully discloses that current GitHub dispatch and artifact reads
are out-of-kernel executor operations under a proof-backed governed phase. It
does not claim that the live connector consumes Workflow OS external-action
capabilities.

## Validation

- official GitHub hosted-runner contract reviewed;
- official Actions artifact retention contract reviewed;
- `npm run check:docs`: passed after correction;
- `git diff --check`: passed after correction.

## Verdict

Accepted with no remaining P0 or P1 blocker in the planning boundary. The next
authorized phase is implementation of the native macOS workflow and symmetric
contract tests only. Workflow dispatch, artifact production, transfer-gate
closure, independent assurance, and publication remain later separately
governed phases.
