## Implemented Contract

### Explicit closed posture

The CLI and exported API require one of exactly two postures:

- `provisional_rehearsal`; or
- `final_candidate`.

The CLI exposes these as mutually exclusive `--provisional` and
`--final-candidate` flags. Missing, conflicting, or unknown posture fails before
binary reads or output creation.

### Non-bypassable final admission

Final posture rejects caller attempts to disable repository or binary
verification. It requires:

- an exact 40-character source commit matching checkout `HEAD`;
- a clean tracked and untracked worktree;
- aligned Rust and npm manifests plus Cargo and npm lockfiles;
- one selected native target on its matching host;
- a native binary matching the target shape, including static linkage for the
  Linux musl target; and
- exact `workflow-os 0.4.0-preview.1` version output.

Provisional rehearsal retains explicit verification bypasses for isolated
contract tests and non-publishing CI. Its v1 manifest records
`provisional_rehearsal`, so it cannot be relabeled as final by renaming files.

### Manifest and output safety

`PACKAGE-MANIFEST.json` now uses
`workflowos.dev/release-package/v1` and records explicit posture, exact source,
clean-tree fact, target, version, binary checksum, install contract, and state
posture.

All validation and deterministic archive construction occurs before output
creation. Existing archive or checksum paths fail closed. Temporary files are
linked into final names without replacing user files, and incomplete packager
output is removed on failure.
