## Findings

### No duplicate dispatch

The local dispatch shell failed after the macOS request because it assigned to
zsh's reserved `status` parameter. Exact-SHA run inventory showed one macOS
run. The Linux API response differed from the caller's expected status code,
so the maintainer did not retry; inventory then showed one Linux run. The final
state contains exactly one terminal-success attempt for each target.

### One machine authority path

The initial evidence edit pointed `candidate_evidence_report_path` at the new
current-source report. The deterministic release-state validator rejected that
split authority because hosted transfer evidence is rooted in the established
scoped-transfer report. The correction restored the existing authority path
and added a superseding current-source addendum there, while retaining the
new report as the detailed phase record. The validator contract was not
weakened.

### Historical evidence remains immutable

The active release-state projection now supersedes source
`21615863b17a49fa14ea0da8e2ad8e327ffa48b1`, but the historical scoped-transfer
facts and hashes remain in the original report. No old digest, source identity,
run, artifact, or conclusion was rewritten as current evidence.

### Claims remain bounded

The reports describe verification outside the producing workflows without
calling it independent assurance. They distinguish the native replay performed
on macOS from the Linux lifecycle enforced by the hosted workflow. They do not
promote seven-day Actions artifacts to published assets or treat candidate
success as publication authority.
