# Local Fixture Replacement Authority Implementation

This slice adds a fixture-only path for a distinct local connector principal.
The original approved request, actor, approval proof, immutable bundle, and
attempted SideEffect remain unchanged. A verified result grants no permission
to dispatch and consumes no grant, window, or attempt.

## Operator And Consumer Boundary

Use the `provider github-pr-comment fixture-authority` operator commands only
against the dedicated `github-pr-comment-continuation.sqlite3` store. V10 adds
empty principal and grant tables. `upgrade` explicitly admits exact V9 state;
schema drift fails closed. The original same-actor command can still inspect
exact V9 read-only. No grant or registration is generated by upgrading.

- `register --actor <id> --harness <id> --credential-stdin` takes exactly 32
  bytes of operator-generated high-entropy credential material on stdin. Only
  the verifier is persisted; it commits to both actor and harness. Provision
  independently generated credentials outside the model or transcript.
- `issue --request <path> --grant-file <path> --operator <actor-id>` takes a
  bounded fixture document with `request` and `fixture`, and a validated
  `CapabilityGrant` declaration. The trusted local operator must be the actor
  who granted the original approval. The grant uses capability reference
  `fixture/github-pr-comment-continuation`, an exact run/step/harness and
  target, the cited approval and check references, no onward delegation, and
  expiry no later than the active window. Issuance atomically checks current
  durable facts and rejects duplicate identities.
- `revoke-grant --grant <id>` and `revoke-principal --actor <id>` permanently
  retire records. Revoked identities cannot be re-registered or reissued.

The consumer command is `provider github-pr-comment continue-sandbox-delegated
--grant <id> --credential-and-request-stdin`. Its stdin frame is 32 raw bytes
of credential followed by UTF-8 JSON containing exactly `request` and
`fixture` (maximum 64 KiB). The transport supplies the credential, not the
model. The kernel authenticates the registered principal and does not accept a
replacement actor or issuer field. The SQLite store is opened read-only.

The final read checks the exact credential registration and grant together
with the original event history, presentation, SideEffect, current window,
attempt, and dispatch reservation. It uses trusted time and compares the
original action, immutable bundle, approval event and presentation proof to
the stored intent commitment. The result reports `verified_delegation`, not
execution, reservation, or future authorization.

## Limits

This is a local trusted-operator contract, not an OS isolation or vendor-account
authentication claim. The app-facing tool must pin the state directory, limit
the fixture inputs, and keep credentials, raw SQLite access, general shell
access, and every operator command outside the model's tool surface. Claude
Desktop configuration and the actual harness corpus are a separate phase.
No provider calls, live writes, credentials for providers, or cross-machine
claim are part of this implementation.

## Validation

- The rebuilt CLI issued and validated a prepared fixture grant on an existing
  database. It rejected an actor override and a wrong credential, left the
  database bytes unchanged during validation, and rejected the revoked grant.
- Core tests covered separate-connection reopen, original issuer matching,
  exact intent and credential matching, expiry, and grant and principal
  revocation. A fresh SQLite snapshot rejected a grant revoked after successful
  preliminary authentication on another connection.
- The Core and CLI unit tests and affected CLI, local executor, SQLite, and
  migration writer suites passed: 1,417 tests; the opt-in live GitHub test was
  ignored. Warnings-denied Clippy for the affected targets, formatting, docs,
  and whitespace checks passed.
