## Implementation

### Machine-readable identity

- all four Rust crates are `0.4.0-preview.1`;
- the root npm package and TypeScript SDK are `0.4.0-preview.1`;
- Cargo and npm lockfiles agree;
- CLI text and JSON version output derive from the CLI crate version; and
- JSON release posture is
  `governed_authority_repository_adoption_preview`.

### Provider identity

The GitHub, Jira, GitHub Actions, and managed draft-PR clients no longer carry
manually synchronized release literals. Core owns compile-time user-agent
constants derived from `CARGO_PKG_VERSION`; the draft-PR proof adds only its
bounded `draft-pr-sandbox` suffix.

Protocol-domain strings such as `workflow-os/.../v1` remain unchanged because
they identify contract algorithms rather than repository release identity.

### Documentation

Current product, CLI, readiness, semantic-versioning, release-process,
security, dependency, and known-limitation documents now identify the `0.4`
preparation posture. Historical `0.3` release records and exact prior evidence
remain unchanged.

New versioned records include:

- release notes;
- release checklist; and
- GitHub Release draft.

Every new release record states that publication remains unauthorized and that
final-candidate and publication gates are still open.
