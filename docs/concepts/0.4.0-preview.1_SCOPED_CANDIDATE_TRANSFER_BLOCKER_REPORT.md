# 0.4.0-preview.1 Scoped Candidate Transfer Blocker Report

Status: transfer blocked after independent artifact verification; publication
remains unauthorized

## Decision

Do not admit the candidate pair built from
`9570b15d1a6a879c92b3a30fb3436b57eb1e0d20` into the active release state.
Both native packages passed independent package verification, but the current
machine-readable release-state validator still encodes the superseded
asymmetric storage posture: local-only macOS evidence and one hosted Linux
artifact. It cannot truthfully represent two exact-source bounded Actions
artifacts.

Changing the validator is a code change after candidate production. The
accepted transfer plan says any post-candidate code change invalidates both
candidates. The pair is therefore useful historical evidence, not the
publishable or admitted pair. After the validator correction is reviewed and
merged, both candidates must be rebuilt from that one new exact commit.

## Blocker

`scripts/check-release-state.mjs` currently requires:

- macOS `storage_posture: local_ignored_dist`; and
- hosted workflow and artifact identity only for Linux.

The accepted transfer contract instead requires both target records to carry
the same bounded hosted-evidence class and to fail closed on mixed source,
workflow identity, terminal conclusion, artifact identity, retention,
checksums, binary identity, and publication authority. Writing the new pair
into the old shape would either fail validation or misrepresent macOS storage.
Neither is acceptable.

## Corrective Scope

The blocker fix introduces a strict symmetric hosted-transfer state while
preserving validation of the current pre-transfer evidence record. The hosted
state requires:

- exactly two selected native targets from one exact source;
- `verified_bounded_actions_artifacts` transfer status;
- one distinct superseded candidate source;
- exact workflow-definition path and commit, run actor, creation, attempt,
  terminal-success, artifact, size, creation, expiry, archive, binary, and
  evidence identities for each target;
- target-derived artifact names and binary shapes;
- exact native version output and candidate-evidence schema;
- an approximately seven-day creation-to-expiry interval with bounded clock
  tolerance; and
- a bounded transfer report in the authority set.

Mixed hosted and local storage fails closed. The active release-state JSON is
not changed in this blocker phase because the current pair is not admitted.
