# 0.4.0-preview.1 Release-State Closure Blocker Fix Report

Status: implemented and validated; focused review required before merge

## Finding

A fresh current-main evaluation found that Workflow OS had merged the final
packaging implementation through PR #712 and the exact-commit Linux candidate
workflow through PR #713, while the authoritative roadmap, accepted plan,
implementation reports, and release checklist still described those
transitions as pending.

This was not a kernel-runtime defect. It was a P1 release-governance truth
defect: candidate dispatch and publication decisions consume those documents
as authority, so their state must agree with Git history.

  merge-close status check, add focused tests, and record the fix
- Strict non-goals: no candidate dispatch, tag, GitHub Release, registry or
  asset publication, announcement, version change, runtime behavior, provider
  write, v1 claim, or independent-assurance claim

## Fix

The change:

- records PR #712 and merge commit
  `0d5a9c2ae26f42fc4efa907942a66e49a9e41c59` as the durable final-packaging
  implementation fact;
- records PR #713 and merge commit
  `b0bbb4994c8b6b9816e43e38eae8cd17005e908a` as the durable Linux candidate
  workflow fact;
- closes the corresponding implementation/review/merge checklist item without
  authorizing dispatch;
- adds `0.4.0-preview.1_RELEASE_STATE.json` as a payload-minimal,
  machine-readable merge-close record;
- adds `check-release-state.mjs` to reject stale transition language, version
  drift, invalid merge identities, merge commits outside current history,
  missing implementation paths, missing PR/commit citations, and an unchecked
  merged-workflow gate; and
- integrates the check into `npm run check:docs` and its focused tests into
  `npm run check`.

The machine-readable record keeps `publication_authorized: false`.
Implementation presence and merge closure do not imply candidate dispatch or
publication authority.

## Candidate Invalidation

An Apple Silicon candidate was produced out of kernel execution from exact
commit `b0bbb4994c8b6b9816e43e38eae8cd17005e908a` before this finding arrived.
Its checksum and behavioral evidence remain useful diagnostic evidence, but it
is not eligible for later publication because this source change moves the
frozen candidate boundary.

After this fix is merged and exact-head CI is green, both macOS and Linux
candidates must be rebuilt from the same new exact merge commit under a new
governed release phase. No Linux dispatch occurred against the invalidated
commit.
