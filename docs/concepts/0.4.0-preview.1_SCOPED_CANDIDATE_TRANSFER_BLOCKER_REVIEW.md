# 0.4.0-preview.1 Scoped Candidate Transfer Blocker Review

Status: accepted after evidence-completeness correction; candidate transfer
and publication remain unauthorized

## Scope

This owner-conducted maintainer and release-security review evaluates the
symmetric hosted-candidate release-state validator, focused tests, blocked
transfer evidence, roadmap statement, and release-checklist posture. It is not
independent assurance and does not authorize candidate production, workflow
dispatch, transfer admission, tagging, release creation, registry publication,
or announcement.

## Finding And Correction

The first implementation correctly rejected mixed hosted and local storage,
required exact source and workflow-definition commits, required successful
runs and bounded artifact metadata, checked archive and binary identities, and
preserved the existing pre-transfer state.

Review found one P1 evidence-completeness gap. The proposed hosted state did
not yet require:

- the exact target-specific workflow definition path;
- the workflow actor and run creation time;
- the candidate-evidence schema version; or
- an approximately seven-day artifact creation-to-expiry interval.

Those facts are required by the accepted transfer plan and are important when
two workflows can otherwise share similar run and artifact identifiers. The
validator and tests now require them. Retention permits a five-minute clock
tolerance around seven days so GitHub timestamp rounding does not create a
false rejection while materially shorter or longer retention still fails.

## Accepted Boundary

The corrected validator supports two explicit postures:

1. the current historical pre-transfer state, with local-only macOS evidence
   and one bounded Linux artifact; and
2. a future symmetric hosted-transfer state requiring both selected targets
   to use `bounded_actions_artifact` and the top-level status
   `verified_bounded_actions_artifacts`.

Any partial hosted transition fails closed. The future hosted state must bind:

- one exact candidate source and one distinct superseded source;
- exact workflow path and definition commit per target;
- run ID, attempt, actor, creation time, and terminal-success conclusion;
- artifact ID, name, size, digest, creation, seven-day expiry, and retention;
- archive name and digest;
- binary digest, native shape, and exact version output;
- candidate-evidence schema and digest;
- one bounded transfer report in the release authority set; and
- publication denial at both release and candidate levels.

The implementation deliberately does not update the active release-state JSON.
The verified artifacts from source
`9570b15d1a6a879c92b3a30fb3436b57eb1e0d20` remain non-admitted historical
evidence because this validator correction changes code after their production.
