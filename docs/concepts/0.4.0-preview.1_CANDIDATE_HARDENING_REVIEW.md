## Findings And Corrections

### P1 corrected: non-regular destination entries were not explicit

The initial patch rejected symlinks and allowed explicit replacement of an
existing path, but it did not explicitly reject directories or other
non-regular entries before the force branch. Existing shell failure behavior
was fail-closed, but the contract was implicit and the diagnostic was weak.

The corrected installer now rejects any existing non-regular destination before
replacement logic. A focused regression creates a destination directory,
supplies `--force`, and proves that the installer refuses it without removing
the entry.

### P1 corrected: Linux evidence tests proved fields, not their inputs

The initial workflow tests required the Linux JSON body to name the symmetric
fields, but did not prove that computed shell values were passed into the Node
evidence writer. A future edit could therefore preserve field names while
silently emitting missing values.

The corrected tests require the Linux workflow to bind `binary_checksum`,
`binary_shape`, and `uname -m` into `BINARY_SHA256`, `BINARY_SHAPE`, and
`NATIVE_MACHINE`. The existing shared assertions continue requiring the fields
in both native evidence bodies.

## Accepted Safety Properties

- A destination symlink is rejected before any destination mutation, whether
  its target exists or is dangling and whether `--force` is present.
- A regular destination requires `--force` before removal.
- A non-regular destination fails closed even with `--force`.
- The source executable is copied only to a private temporary path inside the
  selected directory.
- Final destination creation uses a hard link and therefore fails atomically if
  any path entry appears concurrently.
- A raced destination path is never followed to an external target.
- Temporary cleanup uses portable `/bin/sh` trap posture for supported hosts.
- Install and explicit replacement preserve executable mode and expected
  version output.
- Uninstall remains idempotent and leaves repository state untouched.
- Linux candidate evidence now carries binary hash, native shape, and machine
  fields from computed native values.
