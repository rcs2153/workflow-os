## Corrected Findings

### P0: Final Candidate Could Have Been Minted Through Test Bypasses

The draft allowed callers to disable repository or binary verification in
focused fixtures while selecting final posture. Because the packager is an
exported API, caller intent is not an enforceable security boundary. That would
have allowed `final_candidate` output with no clean-checkout or native-binary
proof.

The plan now requires final posture to reject every verification bypass through
all exported paths. Final tests must use a real temporary clean Git repository
and executable fixture, or a lower-level builder that cannot emit final
posture.

### P1: Active Provider Identity Inventory Was Incomplete

The draft named only the draft-pull-request sandbox user agent, but active
GitHub, Jira, and CI read adapters also contain literal preview identities. The
plan now requires all active provider identities to derive from the crate
version while preserving protocol-domain identifiers and historical evidence.

### P1: Candidate Source Was Not Explicitly Frozen

The draft required exact-commit artifacts but did not state what happens when a
release note, workflow, or decision document changes afterward. The corrected
plan freezes the candidate commit and invalidates both target artifacts after
any source or documentation change.

### P1: Candidate Workflow Supply Chain Was Under-Specified

The draft bounded the source checkout but not the workflow definition or
third-party action revisions that produce transferred candidate artifacts. The
plan now requires immutable workflow/action revisions and separately records a
different workflow-definition commit when applicable. Candidate upload also
requires a scoped external-action authorization distinct from release
publication authority.

## Accepted Limitations

- Checksums provide integrity comparison, not publisher authentication.
- Deterministic archive construction does not claim reproducible binaries.
- macOS binaries remain unsigned and unnotarized unless a later plan explicitly
  adds those capabilities.
- Owner-conducted focused review is not independent external security
  assurance.
- `0.4.0-preview.1` remains a local-first preview, not a v1 or production
  claim.

These limitations must remain prominent in release notes, the candidate review,
and any later publication decision.
